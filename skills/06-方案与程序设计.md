# 06 · 方案与程序设计（as-built：实现说明 + 实测记录）

> 本文件记录**实际实现**（不是最初的构想稿）。最后更新：2026-10-11，程序A 已在本机多轮实测通过；程序B 通过 dry-run 验证。

## 摘要

- **程序A（`start-gpt.cmd`）**：双击 → 按 12 步把网络环境准备到"ChatGPT 全程走美国静态 IP" → 打开 ChatGPT → 打印验证结论。**无需管理员**。全流程实测约 45–60 秒。
- **程序B（`stop-gpt.cmd`）**：双击 → 自动请求 UAC 提权 → 依次关闭 ChatGPT（含 Codex 进程）→ Roxy（窗口/主程序/roxynet）→ 清理系统代理 → Clash Verge（应用 + 内核）→ 关闭项目相关 cmd 窗口 → 终检网络已回到直连。
- **技术路线**：Roxy 窗口 `261011-1` 的美国静态 IP（`<美国静态IP>`）经 **roxynet 本地代理**接入 Clash；Clash 用**扩展文件**定义自定义节点 `GPT-US-Static` + 代理组 `GPT-US` + 8 条规则，把 OpenAI 域名与 ChatGPT/Codex 进程的流量钉到该组；系统代理 + TUN 双通道保证 Electron 层与 Rust 后端都被覆盖。
- **语言与结构**：Node.js（零第三方依赖）+ 两个 `.cmd` 启动器；模块化（`src/lib/*`），函数嵌套不超过 3 层。
- **出口策略（2026-10-11 按用户要求收紧）**：**严格模式 —— 使用 GPT 时必须走美国静态 IP，绝不使用任何其它 IP**。代理组 `GPT-US` 为 `select` 类型且**只含一个成员** `GPT-US-Static`；静态通道不通时 GPT 直接连不上（不会静默换 IP）。其它决策：关闭范围含 Codex 相关进程；开机自启守护为"用户禁用"；未在本机执行程序B的真实拆机流程（仅 dry-run），留给你自行双击验证。

## 一、总体思路（为什么这么做）

| 层 | 走的通道 | 保障手段 |
|---|---|---|
| Electron 前端（ChatGPT.exe） | Windows 系统代理 | 系统代理指向 Clash 7897（程序A校验/修正） |
| Rust 后端（codex.exe / Codex.exe） | 默认不用系统代理 | **TUN 模式**接管（程序A校验） |
| 一切子进程/WebSocket/UDP | 网络层 | TUN（同上） |

"美国静态 IP"的落地：Clash 规则把 OpenAI 流量（进程 + 域名）指到自定义节点，该节点 = `socks5 127.0.0.1:<roxynet端口>`（认证 `dirId:dirId`），roxynet 再把它接到窗口 `261011-1` 的上游美国静态 IP（`<美国静态IP>`）。

## 二、Clash 侧配置（程序A自动维护）

### 2.1 节点（`profiles\pYSK1srNIfYO.yaml`）
```yaml
prepend:
  - name: GPT-US-Static
    type: socks5
    server: 127.0.0.1
    port: <程序运行时探测到的 roxynet 端口>
    username: <窗口 dirId>
    password: <窗口 dirId>
    udp: true
```

### 2.2 代理组（`profiles\gKPowEnXWzil.yaml`，严格模式）
```yaml
prepend:
  - name: GPT-US
    type: select              # 严格模式：组里只有静态节点，结构上不可能走到其它 IP
    proxies: [GPT-US-Static]
    url: https://www.gstatic.com/generate_204
    interval: 60
```
- 程序A 每次运行都会核对组的类型与成员：若发现组里混入了非静态节点（例如被手动改成 fallback），会按 `config.js` 重写文件并重启 Clash 恢复严格性。
- 若确实想临时放宽（可用性优先），把 `src\config.js` 的 `clash.groupType` 改成 `'fallback'` 再跑一次程序A 即可（会加入订阅里的美国节点作兜底）。

### 2.3 规则（`profiles\rQPkKclEsQ5L.yaml`，自上而下首条命中）
```yaml
prepend:
  - PROCESS-NAME,ChatGPT.exe,GPT-US
  - PROCESS-NAME,Codex.exe,GPT-US
  - PROCESS-NAME,codex.exe,GPT-US
  - DOMAIN-SUFFIX,chatgpt.com,GPT-US
  - DOMAIN-SUFFIX,openai.com,GPT-US
  - DOMAIN-SUFFIX,oaistatic.com,GPT-US
  - DOMAIN-SUFFIX,oaiusercontent.com,GPT-US
  - DOMAIN-SUFFIX,ipinfo.io,GPT-US     # 出口校验专用：经 Clash 请求它，返回的即是"当前生效路径"的出口 IP
```

### 2.4 生效判据（程序A每次运行都核对）
1. 扩展文件内容与期望一致（不一致 → 写盘，原文件自动备份 `*.gptproxy-backup`）；
2. **内核里真的加载了**这些节点/组/规则（`GET /proxies` + `GET /rules`）——不一致 → 重启 Clash 应用重新生成配置；
3. `127.0.0.1:7897` 在监听、`Meta` TUN 网卡存在、系统代理指向 7897。

## 三、程序A（`start-gpt.cmd`）执行步骤（实现版）

**顺序原则（关键）**：先把 Clash 与系统代理准备好，**再**启动 Roxy/打开窗口 —— 因为 roxynet 建立"上游跳板链路"时会用到当时的系统代理；顺序反了静态通道会一直 502（程序里有自愈：重启 Roxy 重建链路）。

| # | 步骤 | 关键动作与实测结果 |
|---|---|---|
| 1 | 环境自检 | 打印项目目录、Node 版本、日志文件路径 |
| 2 | 确保 Clash **后台服务**在运行 | 服务停止时用助手计划任务（`GPTProxy-StartClashService`）拉起 —— **无需 UAC**（任务由程序B 在提权时注册） |
| 3 | 确保 Clash 应用 / 内核 / 系统代理就绪 | 启动应用 → 等 7897 → 系统代理指向 7897（这一步必须早于 Roxy） |
| 4 | 确保指纹窗口 `261011-1` 已打开 | **按 dirId 识别**（标题不可靠）；Roxy 未运行时用"带窗口参数的首次启动"（实测可靠）；失败给出人工指引 |
| 5 | 探测 roxynet 代理口 | 枚举 roxynet 监听端口，用 `407 + Proxy-Authenticate: realm=roxynet` 识别代理口（实测不同会话分别为 56632 / 62791 / 49443 / 61337 —— **必须动态探测**） |
| 6 | 校验美国静态 IP 通道（带自愈） | 经 roxynet 请求 ipinfo（重试 3 次）→ 必须 US；若失败且系统代理/Clash 正常 → **自动重启 Roxy 重建链路**（新端口会流到下一步）；严格模式下仍不通则明确报"GPT 将无法联网（不会使用任何其它 IP）" |
| 7 | 同步扩展文件 | 用**最终** roxynet 端口生成节点文件；与磁盘比对，有变化才写（写入前自动备份） |
| 8 | Clash 就绪核对（必要时重启应用） | 判据 = 节点/组存在 **且** `GET /rules` 里能看到全部本项目规则；不满足就重启 Clash 应用；顺便核对 TUN 网卡；严格模式下把组选择钉在静态节点 |
| 9 | 节点连通性测试 | 经 GPT-US 组访问 chatgpt.com（重试 2 次） |
| 10 | 开机自启守护 | ChatGPT StartupTask 若被启用（State=2/4）则置回"用户禁用"（State=1） |
| 11 | 打开 ChatGPT | `explorer.exe shell:AppsFolder\OpenAI.Codex_2p2nqsd0c76g0!App`，等待进程出现 |
| 12 | 终检（三重证据） | ① 经 7897 请求 chatgpt.com，**边发请求边轮询** `/connections` 抓 `chains`；② 经规则路径请求 ipinfo.io 实测出口 IP；③ 应用自身流量的 `chains` |

## 四、程序B（`stop-gpt.cmd`）执行步骤（实现版）

| # | 步骤 | 关键动作 |
|---|---|---|
| 0 | 提权 | 非管理员时用 `tools\elevate.ps1` 请求 UAC，在新窗口继续（原窗口自动关闭）；拒绝提权则给出指引。**每次运行会往 `state\logs\stop-*.log` 写日志**（提权窗口里的输出也能留档） |
| 1 | 关闭 ChatGPT | 温和关窗（有 60 秒超时保护）→ 逐个 `taskkill /IM xxx /T /F`；范围含 `Codex.exe`、`codex.exe` |
| 2 | 关闭 Roxy | 温和关窗（60 秒超时）→ 强杀 `RoxyChrome.exe` → `RoxyBrowser.exe` → `roxynet.exe` |
| 3 | 清理系统代理 | `ProxyEnable=0` + WinINET 通知（避免指向已关闭端口） |
| 4 | 关闭 Clash Verge | ① 注册/确认助手计划任务 → ② 杀应用 → ③ **停止 `clash_verge_service` 服务（内核随服务一并结束）** → ④ 兜底（SeDebugPrivilege 脚本） |
| 5 | 关闭项目窗口 | 标题含 `GPT-Proxy-` 或命令行含本项目启动器/脚本特征的窗口逐个关闭；**跳过自身及自身祖先进程链**（避免误杀调用方） |
| 6 | 终检 | 7897 不再监听、`Meta` 网卡消失、系统代理=0（若被 Clash 退出动作改回开启会再清一次）、GPT/Roxy 进程已退出、直连出口 IP 可查 |

**为什么是"停服务"**：实测"只杀内核"会被服务自动拉起（内核 PID 从 37692 变成 38292）；`Stop-Service clash_verge_service` 会连带结束内核，且**不会**被自动重启。代价是服务被停 → 由程序A 的助手任务负责恢复（见程序A 步骤 2）。
保留项：`CodexSandboxService` 服务不停止（与应用启停无关）。

**已知限制与处置**
| 限制 | 现状 | 处置 |
|---|---|---|
| roxynet 端口动态 | 每次运行重新探测 | 已实现（写进扩展文件时同步刷新） |
| **严格模式下的可用性**（当前设置的代价）| 静态通道不通时，GPT 会直接无法联网（这是刻意的：宁可用不了，也不用非静态 IP） | 程序A 会明确报出"GPT 将无法联网（不会使用任何其它 IP）"并给出排查提示；修好静态通道（Roxy 窗口/roxynet/上游服务）后重跑程序A 即可 |
| fallback 组健康检查偶发抖动（仅 fallback 模式存在） | 观察到短暂切到备用节点后自动切回 | fallback 模式下 healthCheck 间隔 60 秒，且程序A在确认静态通道可用后主动刷新健康；当前为 select 模式，不存在此问题 |
| Clash 重启后旧连接不改道 | 应用的长连接可能仍挂在旧节点上 | 报告口径只认"新建连接"的证据；静态通道确认可用后再触发健康刷新，新连接即走静态 IP |
| Roxy 未文档化 CLI 不稳定 | 窗口已开着时第二实例送达不可靠 | 优先按 dirId 识别已打开窗口；仅在确实没开时尝试 CLI，失败给出人工指引；建议（可选）在 Roxy 里开启本地 API 以获得官方开关窗能力 |
| 程序B 强制关闭 Roxy | 会跳过云端同步（本机 Roxy 的定时同步窗口为 3 分钟，多数情况下数据已同步） | 若窗口里刚做过重要操作，先在 Roxy 托盘"退出"再运行程序B |
| 关闭 Clash 内核需管理员 | 内核为 SYSTEM 身份 | 程序B自动请求 UAC；拒绝则只完成用户级清理并给出指引 |

**运维要点（改代码必读）**
1. `src\tools\*.ps1` 必须保存为 **UTF-8 带 BOM**：Windows PowerShell 5.1 会把"无 BOM 的 UTF-8"按 GBK 解码，中文会导致解析失败（本项目已踩坑并修复）。用编辑器修改后请确认 BOM 仍在（文件头 `EF BB BF`）。
2. `clash-verge.yaml` / `config.yaml` 是应用生成物，永远不要手改；本项目只写 `profiles\` 下 3 个扩展文件。
3. 三个扩展文件的托管内容由 `src\lib\clash-profile.js` 生成：如需增删规则/节点，改 `src\config.js` 后重跑程序A（会自动重写并重启 Clash）。
4. 若在 Clash Verge 界面里手动"编辑规则/节点/代理组"，会覆盖本项目的托管内容（覆盖前有 `*.gptproxy-backup` 备份可回滚）。
